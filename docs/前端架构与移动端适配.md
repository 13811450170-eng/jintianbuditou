# 前端架构与移动端适配

## 目标

现阶段保留零构建、浏览器直接运行的方式，不一次性重写框架。新代码按分层组织，逐页把 HTML 中的逻辑迁出，最终让桌面端和移动端复用同一套业务能力。

## 分层

```text
HTML pages
  └─ 页面结构与少量页面入口
styles/
  ├─ tokens.css        全局尺寸、间距、圆角、安全区、触控目标
  └─ mobile.css        移动端布局契约与断点
js/core/
  ├─ app-shell.js      viewport、设备状态、动态视口高度、页面 ready 事件
  └─ dom.js            安全 DOM 操作与转义
js/services/
  └─ api.js            API 超时、错误归一化、JSON 解析、降级请求
js/
  ├─ health-store.js   健康领域本地数据仓库
  ├─ assessment.js     健康评估业务流程
  └─ pose-*.js         MediaPipe 能力层
server/
  ├─ index.js          同源静态服务与 API 路由
  └─ adapters/         DeepSeek、规则降级、商品等服务适配器
```

## 页面职责

- `index.html`：首页组合与入口，不新增健康规则。
- `mock-onboarding.html`：首次资料采集与测量流程；API 统一走 `services/api.js`。
- `zone.html`：关卡列表和评估闸门，不自行实现评估规则。
- `mock-report.html`：只负责报告组合和渲染，健康档案从 `health-store.js` 读取。
- `mock-body-profile.html`：档案查看、编辑、导出和清除。

## 移动端契约

1. 所有核心页面加载 `tokens.css`、`mobile.css` 和 `app-shell.js`。
2. 主断点为 `768px`，极窄屏补充断点为 `390px`。
3. 可点击目标不小于 `44px`；移动端输入字号不低于 `16px`，避免 iOS 自动缩放。
4. 使用 `env(safe-area-inset-*)` 兼容刘海屏、灵动岛和底部 Home Indicator。
5. 高度使用 `--app-vh`，避免移动浏览器地址栏导致 `100vh` 抖动。
6. 浮层在移动端使用底部面板布局，内容区域必须允许滚动。
7. 摄像头、模型或后端不可用时必须显示状态，不允许静默进入正常强度训练。

## 新功能规则

- 网络请求不得在页面内重复写 `fetch + AbortController`，统一使用 `postJSON` 或 `postJSONSafe`。
- 模型输出和用户文本默认使用 `textContent`；确需模板字符串时使用 `escapeHTML`。
- 健康档案读写统一经过 `health-store.js`，页面不得直接定义第二套数据结构。
- 共享视觉变量放 `tokens.css`；页面专属美术仍留在页面样式，稳定后再迁出。
- 新业务优先创建独立模块，HTML 内联脚本只保留页面编排代码。

## 后续迁移顺序

1. 将 `mock-onboarding.html` 的九步流程拆为 `pages/onboarding/` 下的 step modules。
2. 将报告卡片拆为 `components/report/` 组件。
3. 将身体档案展示和编辑拆为 `pages/profile/`。
4. 最后把各页面内联 CSS 迁到 `styles/pages/`，避免先动视觉再动业务造成大面积回归。
