# 颈肩健康知识库

> **用途**：为 `health-assessment`（前期筛查与基线）和 `health-coaching`（练习指导）提供统一的专业依据与使用边界。
>
> **定位**：本文件服务于办公室久坐人群的低负荷颈肩活动与动作控制练习；不用于远程诊断疾病，不构成个体化治疗或康复处方。
>
> **更新原则**：动作、筛查规则或面向用户的健康表述发生变化时，应同步核对本文件的来源与边界。

## 1. 使用原则

1. 所有动作均在舒适、无痛、缓慢且受控的范围内完成。
2. 不以疼痛、极限幅度、快速次数或游戏得分作为练习目标。
3. 每次单一方向动作完成后，先回到自然中立位，再进行下一次动作。
4. 摄像头数据只用于描述个人动作完成情况、代偿和识别质量；不输出临床诊断、标准活动度结论或疗效承诺。
5. 发现安全警示信号时，停止本次动作游戏，并建议用户进行线下专业评估。

## 2. 专业资料及其使用范围

| 来源 | 在产品中的用途 | 不用于 |
|---|---|---|
| MDT（McKenzie Method / Mechanical Diagnosis and Therapy） | 多方向重复动作、症状变化和活动表现的观察逻辑 | 自动 MDT 分类、方向偏好判断、诊断或处方 |
| JOSPT/APTA《Neck Pain: Revision 2017》 | 安全筛查、转介边界、运动干预的临床边界 | 根据游戏表现判断颈椎疾病或康复疗效 |
| NHS / NHS 医院物理治疗资料 | 动作原名、动作要点、舒适范围与常见代偿 | 针对具体疾病的治疗承诺 |
| 中国康复医学会《颈椎病诊治与康复指南（2010）》 | 国内语境下的缓慢颈部活动和久坐改变体位的背景 | 唯一或最新临床证据 |
| 办公人群运动研究 | 项目价值与“活动 + 规律间歇 + 工位调整”的组合思路 | 对单个用户作因果疗效结论 |
| HSE / OSHA 办公工位资料 | 规律休息、姿势变化和基础工位提醒 | 医疗诊断或治疗建议 |

## 3. 练习前安全自查与练习路径判定

本节供 `health-assessment` 使用。“安全警示信号（红旗）”是指不适合继续自行进行颈肩练习、需要优先进行线下医疗评估的信号；它不用于诊断具体疾病。

### 3.1 共同安全警示信号

若用户报告近期颈肩外伤、疼痛快速或持续加重、发热不适、胸痛或呼吸困难、持续或进行性麻木/无力等，应停止本次筛查和动作练习，建议线下医疗评估。

### 3.2 颈部相关安全警示信号

若用户报告明显手脚无力或笨拙、走路不稳、吞咽或呼吸困难、异常剧烈头痛或眩晕、大小便功能新变化等，不进行颈部基线动作，并建议线下医疗评估。

### 3.3 肩部相关安全警示信号

若用户报告肩部或手臂明显变形/肿胀、急性受伤后剧痛、无法正常抬臂、持续麻木或无力等，不进行肩部基线动作，并建议线下医疗评估。

### 3.4 练习路径

| 筛查与基线结果 | 系统建议 |
|---|---|
| 颈部、肩部均通过 | 可进入当前通过基线的颈部和肩部低负荷动作 |
| 仅颈部通过 | 仅开放颈部动作；关闭肩部动作 |
| 仅肩部通过 | 仅开放肩部动作；关闭颈部动作 |
| 任一共同安全警示信号，或两个部位均未通过 | 不进入动作游戏，建议线下专业评估 |
| 识别质量不足 | 提示调整坐姿、光线或摄像头位置后重测；不输出基线结论 |
| 检测到快速甩动 | 立即停止该次计分，提示放慢并回到中立位；该动作控制事件不等同于医疗安全警示信号 |

## 4. 基线记录原则

### 4.1 主观不适基线

- 分别记录颈部、左肩和右肩的当前不适评分（0–10）。
- 记录不适区域：颈部、肩部、上臂或无明显不适。
- 记录动作过程中是否出现不适、眩晕、麻木或无力。
- 第一版不强制使用长问卷。哥本哈根颈部功能障碍量表（CNFDS）可作为后续研究或试点的可选功能，而非游戏准入门槛。

### 4.2 颈部多方向基线（参考 MDT 评估逻辑）

产品参考 MDT 的“在不同方向重复动作后观察症状与活动表现”的逻辑，将前突、屈曲、后缩、伸展、左/右侧屈、左/右旋转整理为 8 个基线记录维度。

这 **不是 MDT 官方固定命名的“标准八向处方”**。系统只记录个人舒适范围内的完成情况、代偿、主观不适和追踪置信度；不将结果表述为临床 ROM、方向偏好或疾病结论。

| 方向 | 重点记录 | 常见代偿 |
|---|---|---|
| 前突 / 后缩 | 前后平移的完成情况、主观不适 | 低头、翘下巴、躯干前倾/后仰 |
| 屈曲 / 伸展 | 缓慢完成情况、主观不适 | 躯干前屈/后仰 |
| 左右侧屈 | 左右差异、主观不适 | 耸肩、躯干侧倾、转头 |
| 左右旋转 | 左右差异、主观不适 | 躯干跟转、耸肩 |

正面单摄像头对头部前后平移的量化可靠性有限。对于前突和后缩，产品仅输出完成度、代偿和追踪置信度，不输出具有临床意义的距离或角度。

### 4.3 肩部轻量基线

肩部基线只用于决定当前低负荷肩部动作是否可用，不替代肩关节疾病评估，也不输出临床 ROM 结论。

| 基线动作 | 重点记录 | 常见代偿 |
|---|---|---|
| 左右手臂前举 | 相对抬臂高度、左右差异、主观不适 | 耸肩、躯干后仰/侧倾 |
| 坐姿肩胛后缩 | 完成情况、主观不适 | 耸肩、抬下巴、过度挺胸/后仰 |

## 5. 低负荷动作库

动作库只作为游戏玩法的理论来源和专业参考。所有动作都应在舒适、无痛的范围内缓慢完成；出现疼痛、眩晕、麻木、无力或明显不适时应停止。

### 5.1 颈部屈曲（Cervical Flexion）

- **动作说明**：坐位自然放松，缓慢低头，让下巴向胸前靠近至舒适范围，随后回到中立位。
- **动作控制**：观察是否用躯干前屈代替颈部动作。
- **注意事项**：不以双手压头，不追求极限幅度。

### 5.2 颈部伸展（Cervical Extension）

- **动作说明**：建立舒适中立位后，缓慢抬头向上看至舒适范围，随后回到中立位。
- **动作控制**：观察是否用躯干后仰代替颈部动作。
- **注意事项**：只在单一伸展平面完成；不叠加左右转头，不做绕环。

### 5.3 颈部侧屈（Cervical Lateral Flexion）

- **动作说明**：平视前方、双肩自然下沉，缓慢将一侧耳朵向同侧肩膀靠近；在舒适范围内回正后，再进行另一侧。
- **动作控制**：观察耸肩、躯干侧倾和转头代偿。
- **注意事项**：不使用手部加压，不向疼痛方向强行增加幅度。

### 5.4 颈部旋转（Cervical Rotation）

- **动作说明**：保持躯干稳定、肩膀放松，缓慢将头转向一侧，在舒适范围内回到中立位，再进行另一侧。
- **动作控制**：观察躯干是否跟随旋转。
- **注意事项**：两侧不必强求相同幅度；不自行施加末端压力。

### 5.5 头部前突（Cervical Protrusion，后期扩展）

- **动作说明**：坐直、平视前方，头部缓慢水平向前移动至舒适范围，不低头；随后回到自然中立位。
- **当前定位**：作为 MDT 多方向基线的后期扩展动作，当前不对应游戏玩法。
- **注意事项**：不将前突理解为长期维持头前伸姿势；不以躯干前倾代替平移。

### 5.6 头部后缩（Cervical Retraction / Chin Tuck，后期扩展）

- **动作说明**：坐直、平视前方，将头部缓慢、水平地向后移动至舒适终点，短暂停留后回到自然中立位。
- **当前定位**：作为 MDT 多方向基线的后期扩展动作，当前不对应游戏玩法。
- **注意事项**：不翘下巴、不后仰、不耸肩、不用手加压。

### 5.7 坐姿肩关节前屈（Seated Shoulder Flexion）

- **动作说明**：坐直，手臂缓慢向身体前上方抬起，只到仍能维持肩胛控制的舒适高度，再受控放回。
- **动作控制**：观察耸肩、肋骨上翻、躯干后仰或侧倾。
- **注意事项**：不要求过头；出现疼痛或动作质量明显下降时停止。

### 5.8 坐姿肩胛后缩（Seated Scapular Retraction / Shoulder Blade Squeeze）

- **动作说明**：坐直或站直，肩膀自然放松；轻轻将两侧肩胛骨向后、向下靠拢，短暂停留后完全放松并回到自然位置。
- **动作控制**：观察耸肩、抬下巴、躯干后仰和过度挺胸。
- **注意事项**：不需要用力夹紧肩胛骨；训练目标是温和的肩胛控制，而不是大幅后仰或扩胸。

## 6. 办公室场景建议

动作练习应与减少持续静态坐姿、规律短暂休息和基础工位调整结合。

- 长时间连续使用电脑时，应安排短暂的休息、起身或改变活动，而非只依赖一次拉伸。
- 提醒用户保持头颈与躯干大致对齐、肩膀放松；键盘和鼠标应尽量放在容易触及的位置，避免反复耸肩或远距离伸手。
- 游戏中的工位提醒应使用健康促进语言，例如“换个姿势、起身活动一下”；不应以医疗诊断或治疗语气呈现。

## 7. 训练后反馈与报告边界

### 7.1 练后反馈

记录练前/练后不适评分、动作是否更受限、是否出现新的麻木、无力、眩晕或症状向上肢延伸。出现上述异常或不适持续加重时，应停止继续练习并建议线下评估。

### 7.2 可以呈现的数据

- 练习次数、持续天数、动作完成率和中断次数。
- 动作质量指标：代偿提示次数、节奏稳定性、甩头次数与识别置信度。
- 主观数据：练前后不适评分及其周度趋势。

### 7.3 不可以呈现的结论

- 具体疾病诊断。
- “临床活动度正常/异常”的结论。
- “颈椎已经康复”“某个动作治疗有效”等疗效承诺。

推荐表述为：“动作完成能力、练习参与度和自我报告舒适度的变化”。

## 8. 量化记录与数据解释

本节定义产品可记录的行为与质量数据，用于动作过程反馈、周报和后续实测评估。除主观不适评分外，所有摄像头指标均为**个人相对表现指标**，不替代临床关节活动度测量，也不与“正常角度”比较。

### 8.1 主观不适与安全事件

| 指标 | 记录方式 | 使用边界 |
|---|---|---|
| 颈部、左肩、右肩不适评分 | 练习前后分别由用户自评 0–10 分 | 用于观察个人自我报告的短期变化，不推断治疗效果 |
| 新发不适事件 | 记录眩晕、麻木、无力、疼痛加重或向上肢延伸等用户报告 | 任一事件均应触发暂停提示与安全路径复核，不由系统判断疾病 |
| 传感器动作控制事件 | 记录关卡检测到的甩头次数、快速移动、未回中立位等；与用户自报分开存储 | 立即停止该次计分并给出“放慢、回中立位”提示；不解释为医学红旗或疾病信号 |
| 中断原因 | 用户主动结束、动作不适、识别不足或其他原因 | 用于改进动作和体验，不作健康状况结论 |

建议呈现“本次练前后自我感受”和“近 7 天自我报告趋势”，不把单次评分变化表述为疼痛治疗或康复成效。

### 8.2 动作参与与完成情况

| 指标 | 建议口径 | 可呈现的含义 |
|---|---|---|
| 目标动作数 | 本次计划要求的有效动作次数 | 本次计划规模 |
| 有效完成数 | 满足动作起止、方向与基本质量要求的动作次数 | 完成的练习量 |
| 动作完成率 | 有效完成数 ÷ 目标动作数 | 对当前计划的参与和完成情况 |
| 稳定停留时长 | 在目标姿势中、无明显代偿的累计有效时间 | 控制稳定性，不代表肌力或康复效果 |
| 练习连续天数、周练习次数 | 按完成一次有效练习会话计数 | 练习参与度与习惯趋势 |

当识别结果不足以判定动作是否有效时，不计入“有效完成数”，并应向用户说明是需要重测或调整环境，而不是动作失败。

### 8.3 动作质量与个人相对表现

| 指标 | 建议口径 | 使用边界 |
|---|---|---|
| 代偿率 | 出现耸肩、躯干跟转、躯干侧倾/后仰等代偿的有效尝试数 ÷ 有效尝试总数 | 用于提示动作控制，不判断病因或身体异常 |
| 节奏稳定性 | 有效动作时长或速度与个人本次目标节奏的偏离程度 | 用于提示“放慢、回中立位”，不追求速度 |
| 甩头次数 | 同一关卡内由速度护栏识别并去重的快速头部动作次数 | 用于暂停计分和练后动作控制提示；提醒阈值由关卡调参版本定义，不是医学阈值 |
| 左右相对差异 | 同一次可可靠识别的左右侧完成表现差异 | 仅作个人追踪；不标记“异常” |
| 相对舒适范围 | 当前可舒适完成的动作表现 ÷ 该用户首个可靠基线表现 | 仅适用于同一摄像头设置、同一动作和可比条件；不输出角度或临床 ROM |

“首个可靠基线”应指无安全警示信号、识别质量达标、动作过程中无明显不适的一次个人记录。基线变化可能受坐姿、机位和衣着影响，因此需要保留测量条件并提示用户在相近条件下复测。

### 8.4 识别质量与重测条件

| 指标 | 建议口径 | 产品处理 |
|---|---|---|
| 有效识别帧率 | 可稳定获取所需关键点的画面帧数 ÷ 总画面帧数 | 不足时不输出基线或动作质量结论 |
| 关键点置信度 | 头部、肩部及躯干关键点的模型置信度与连续性 | 用于判断是否需要调节机位，不显示为医疗数据 |
| 遮挡与出框 | 人脸、肩部或上半身被遮挡/超出画面的比例 | 提示露出上半身、移开遮挡物或调整距离 |
| 环境条件 | 光线、逆光、多人入镜、摄像头高度和取景范围 | 作为重测说明和后续模型测试维度 |

具体阈值不应直接套用医学常模，而应通过内部试测确定：先收集不同身高、坐姿、光线、衣着和摄像头位置下的样本，再选取能稳定区分“可测”与“不可测”的产品阈值。阈值调整后应记录版本，保证周报前后可解释。

### 8.5 周报与效果数据的表达

周报优先呈现以下三类信息：

1. **参与度**：练习天数、有效完成率、平均单次时长与中断原因。
2. **动作控制趋势**：代偿提示次数、节奏稳定性和相对舒适范围的个人趋势。
3. **自我感受与数据可信度**：练前后不适评分趋势、识别质量、是否存在不可比的测试条件。

可用表述示例：“本周完成 4 次练习，动作完成率较上周提高；在相近拍摄条件下，肩胛后缩的耸肩提示减少；练后自评舒适度的变化请结合自身感受观察。”

不得表述为“颈椎角度恢复正常”“肩部功能改善 X%”“游戏治疗有效”或其他临床效果结论。

### 8.6 上线前实测与验证

为形成有说服力的量化效果数据，产品应区分“算法有效性”和“使用体验变化”两类验证：

| 验证对象 | 建议方法 | 输出示例 |
|---|---|---|
| AI 动作识别 | 由人工复核视频片段，与系统的动作次数、方向、代偿提示逐项比对 | 有效动作识别一致性、代偿提示准确性、无效识别原因 |
| 环境鲁棒性 | 在不同光线、机位高度、坐姿、距离、遮挡和多人背景下重复测试 | 各场景下的可用率与重测率 |
| 练习参与 | 试点前后比较练习完成率、连续参与天数、单次中断原因 | 参与度与留存变化，不作医疗疗效推断 |
| 自我报告 | 连续记录练前后不适评分与主观易用性 | 自我报告趋势及样本量、周期、缺失数据说明 |

任何面向答辩、汇报或对外传播的“效果数据”，都应同时注明样本量、观察周期、数据收集方式、排除条件和“非医疗诊断/疗效研究”的解释边界。

## 9. 两个 Skill 的引用范围

| Skill | 应使用的章节 | 主要职责 |
|---|---|---|
| `health-intake` | 第 1、2、6 节 | 进入练习前采集用户背景资料(年龄、职业、久坐与用屏时长、既往不适、主诉部位),生成健康促进语言的意图画像,交给 `health-assessment` 作 pre 背景；不诊断、不做安全判定 |
| `health-assessment` | 第 1、3、4、7、8 节 | 判断是否可进入动作练习、可练部位、是否需重测或暂停，并输出可解释的基线和数据质量状态 |
| `health-coaching` | 第 1、5、6、7、8 节 | 在已通过筛查的前提下，给出可用动作、动作控制提示与规律休息建议，并记录可解释的过程数据 |

两个动作类 Skill（`health-assessment`、`health-coaching`）均不得超出第 1 节和第 7 节的边界；`health-intake` 只做背景采集，不得输出任何安全或可练结论。

### 9.1 服务端接入的兼容边界

Skill 的目标语义使用 `available`、`limited`、`remeasure`、`stop` 四态，便于把“可练”“降低负荷”“调整环境重测”和“停止并建议线下评估”清楚分开。与 PR #4 对齐的服务端若仍使用 `pass | refer` 二态接口，应在适配层同时保留两套字段：`pass` 对应 `available/limited`，`refer` 对应 `remeasure/stop`；前端再根据四态字段决定显示“重测”还是“停止”。

传感器记录的甩头等事件必须作为独立的 `sensorEvents` 传给筛查与练后指导，不得塞入用户自报的 `reportedEvents`。它负责动作控制、暂停计分与提示，不单独构成医疗分流依据。
